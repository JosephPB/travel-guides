# never a lonely planet with you

A private, two-person travel notebook with Beirut and Bristol guidebooks. React, TypeScript, Vite and Supabase; GitHub Pages deployment files are prepared, but no repository or live site has been created.

## Run

Use Node 24. Run `npm ci`, then `npm run dev`. The supplied public Supabase configuration is saved locally in ignored `.env.local`; for another machine copy `.env.example` and enter your project URL and publishable key.

- `http://127.0.0.1:5173/` — connected app; sign-in and membership are required before the coffee table.
- `http://127.0.0.1:5173/?preview=1` — development-only preview. Reports reset on reload; the person selector is not authentication.
- `npm test` — PostgreSQL RLS/ownership and content integrity tests.
- `npm run build` — TypeScript checks and production build.

## Included

Photo-only landing, lowercase vector logo, responsive guidebooks, page-turn animation and swipe controls, café search and filters, independent reports with 0–9 triangle-side scores, observations, recommendations, account settings, and adding/editing/deleting your own cafés. Both members read the common notebook; each controls their own entries. Seeded editorial places cannot be edited in the app.

Beirut has 18 sourced entries checked on 16 October 2026, with eight article photos. Entries without supplied venue photos use name tiles. Bristol is empty. Source evidence, exclusions and photo limitations are in [CAFE_SOURCES.md](docs/CAFE_SOURCES.md). Descriptions are brief paraphrases, not copied articles. Operating evidence is dated, not a live guarantee.

## Finish setup

1. Follow [SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md): run SQL, create two auto-confirmed username/password accounts and add their IDs to the allowlist. No SMTP is required.
2. Complete the live two-account checklist there. Local PostgreSQL tests do not replace real account/login checks.
3. When ready to publish, follow [DEPLOYMENT.md](docs/DEPLOYMENT.md). Publishing has intentionally not been performed.

Optional photo uploads are not included; no Storage bucket is needed. Other chapters remain placeholders. Public frontend assets and editorial data are not private; personal notebook data is protected by Supabase policies.

## Maintenance

App screens: `src/main.tsx`; components/forms: `src/components.tsx`; styling: `src/style.css`; Auth: `src/Auth.tsx`; API: `src/data.ts`. SQL lives in `supabase/migrations`. Source café data is `src/data/cafes.json`; run `npm run seed:generate` after changing it. Existing seeded rows are intentionally not overwritten: use an explicit reviewed UPDATE migration for changes to a live database. Keep the one-time setup file synchronized with migrations.

Original photo/logo assets are retained. The plant-free landing image was AI-edited; its prompt is in `IMAGE_EDIT_PROMPT.md`. Current logos are outlined SVGs generated by `scripts/build-logo.mjs`; generation is optional and requires an installed font path.
