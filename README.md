# never a lonely planet with you

A private, two-person travel notebook with Beirut and Bristol guidebooks. React, TypeScript, Vite and Supabase; Live site: https://josephpb.github.io/travel-guides/ . Updates are prepared locally for the owner to deploy.

## Run

Use Node 24. Run `npm ci`, then `npm run dev`. The supplied public Supabase configuration is saved locally in ignored `.env.local`; for another machine copy `.env.example` and enter your project URL and publishable key.

- `http://127.0.0.1:5173/` — connected app; sign-in and membership are required before the coffee table.
- `http://127.0.0.1:5173/?preview=1` — development-only preview. Reports reset on reload; the person selector is not authentication.
- `npm test` — PostgreSQL RLS/ownership and content integrity tests.
- `npm run build` — TypeScript checks and production build.

## Included

Photo-only landing, lowercase vector logo, responsive guidebooks, page-turn animation and swipe controls, café search and filters, independent reports with 0–9 triangle-side scores, observations, recommendations, account settings, and adding cafés, editing shared café details and deleting your own cafés. Both members read the common notebook; each controls their own entries. Both members can edit seeded café details. Each person edits their own reports and recommendations; both can read them. Changes refresh every 30 seconds while the tab is visible and no form has unsaved changes, and on return to the tab.

Beirut has 19 sourced entries checked on 16 October 2026, with venue images for every entry, including Oak Coffee Shop in Forn el Chebbak. Bristol is empty. Source evidence, exclusions and photo limitations are in [CAFE_SOURCES.md](docs/CAFE_SOURCES.md). Descriptions are brief paraphrases, not copied articles. Operating evidence is dated, not a live guarantee.

## Finish setup

1. Follow [SUPABASE_SETUP.md](docs/SUPABASE_SETUP.md): run SQL, create two auto-confirmed username/password accounts and add their IDs to the allowlist. No SMTP is required.
2. Complete the live two-account checklist there. Local PostgreSQL tests do not replace real account/login checks.
3. When ready to publish, follow [DEPLOYMENT.md](docs/DEPLOYMENT.md). This update has not been pushed or published.

Both members can upload JPEG, PNG or WebP photos up to 6 MB per file. Files live in the private `guide-photos` Storage bucket; ownership and café references live in `place_photos`. Both members see the gallery; only the uploader can delete an upload. Signed links expire after one hour. Other chapters remain placeholders. Public frontend assets and editorial data are not private; personal notebook data is protected by Supabase policies.

## Maintenance

App screens: `src/main.tsx`; components/forms: `src/components.tsx`; styling: `src/style.css`; Auth: `src/Auth.tsx`; API: `src/data.ts`. SQL lives in `supabase/migrations`. Source café data is `src/data/cafes.json`; run `npm run seed:generate` after changing it. Existing seeded rows are intentionally not overwritten: use an explicit reviewed UPDATE migration for changes to a live database. Keep the one-time setup file synchronized with migrations.

Original photo/logo assets are retained. The plant-free landing image was AI-edited; its prompt is in `IMAGE_EDIT_PROMPT.md`. Current logos are outlined SVGs generated by `scripts/build-logo.mjs`; generation is optional and requires an installed font path.
